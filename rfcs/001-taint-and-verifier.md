# Taint analysis and verification contracts

The TypeScript checker supplies symbol identities and follows module exports. Forward evaluation carries source locations, object fields, and helper targets. Assignments and parameter binding add trace hops. Branches merge their flows, with a bounded number of retained traces. YAML version 1 controls the recognized sources, sinks, and supported guard forms.

A finding identifies a rule and a source span. SARIF serializes the selected flow in evaluation order. Rankers alter result order through a score, with file, source offset, and rule as tie breakers.

Repair templates match the diagnosed source span against the parsed AST. They print only changed nodes and a fresh helper import. Application rejects overlapping spans. A caller supplies the trusted guard module and any path or host policy required by the template.

Verification begins with a trusted baseline observation. A passing observation refuses the case before an edit can be proposed. For a failing baseline, the verifier checks benign behavior, applies the proposed edit to an in-memory copy, type-checks it, repeats the baseline contract, checks supplied regression inputs, and compares benign observations over fast-check samples. Callback errors fail the current stage. Source under review is treated as data by the harness.

The evaluator has limited control-flow and alias models. It does not resolve code generated by `eval` or `new Function`, runtime monkey-patching, or the effects of arbitrary code in minified bundles. Lifecycle auditing uses syntax and recognizable dataflow patterns for selected shell commands and JavaScript calls.
